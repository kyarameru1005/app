# common_api_design.md

## 1. API設計方針

本システムのAPIは、以下の方針で設計する。

- 認証系、メモ系、カテゴリ系に分けて管理する
- HTTPメソッドは用途に応じて使い分ける
- JSON形式でリクエスト / レスポンスを扱う
- ログイン中ユーザーの識別はセッションにより行う
- `user_id` はフロントエンドから受け取らず、バックエンド側でセッションから取得する

---

## 2. HTTPメソッド方針

| メソッド | 用途 |
|---|---|
| `GET` | データ取得 |
| `POST` | 新規作成、認証開始、ログアウト |
| `PUT` | 更新 |
| `DELETE` | 削除 |

---

## 3. API一覧

### 3.1 認証系API

| API名 | メソッド | パス | 概要 |
|---|---|---|---|
| ログイン開始API | `POST` | `/api/auth/google/login` | Googleログイン処理を開始する |
| ログインコールバックAPI | `GET` | `/api/auth/google/callback` | Google認証結果を受け取り、アプリ内ログイン処理を行う |
| ログアウトAPI | `POST` | `/api/auth/logout` | ログイン中のセッションを終了する |
| ログインユーザー取得API | `GET` | `/api/users/me` | ログイン中ユーザー情報を取得する |

### 3.2 メモ系API

| API名 | メソッド | パス | 概要 |
|---|---|---|---|
| メモ一覧取得API | `GET` | `/api/memos` | メモ一覧を取得する |
| メモ詳細取得API | `GET` | `/api/memos/{memo_id}` | 指定したメモの詳細情報を取得する |
| メモ新規作成API | `POST` | `/api/memos` | 新しいメモを登録する |
| メモ更新API | `PUT` | `/api/memos/{memo_id}` | 指定したメモを更新する |
| メモ削除API | `DELETE` | `/api/memos/{memo_id}` | 指定したメモを削除する |

### 3.3 カテゴリ系API

| API名 | メソッド | パス | 概要 |
|---|---|---|---|
| カテゴリ一覧取得API | `GET` | `/api/categories` | カテゴリ一覧を取得する |
| カテゴリ新規作成API | `POST` | `/api/categories` | 新しいカテゴリを登録する |
| カテゴリ更新API | `PUT` | `/api/categories/{category_id}` | 指定したカテゴリを更新する |

---

## 4. ステータスコード方針

| ステータスコード | 意味 |
|---|---|
| `200 OK` | 正常終了 |
| `400 Bad Request` | 入力値不正、不正なリクエスト |
| `401 Unauthorized` | 未ログイン、認証失敗 |
| `403 Forbidden` | 権限不足 |
| `404 Not Found` | 対象データなし |
| `409 Conflict` | 一意制約違反、重複データ |
| `500 Internal Server Error` | サーバ内部エラー |

---

## 5. 認証・権限制御方針

### 5.1 認証
- Googleアカウントログインを利用する
- ログイン成功後、セッションに `user_id` を保持する
- API実行時はセッションから `user_id` を取得してログイン中ユーザーを識別する

### 5.2 権限制御
- メモはログイン中ユーザー本人のデータのみ操作可能とする
- カテゴリは全ユーザー共通とする

### 5.3 未ログイン時
- 保護対象APIへのアクセスは `401 Unauthorized` を返す

---

## 6. リクエスト / レスポンス共通方針

### 6.1 リクエスト
- `GET` はパスパラメータまたはクエリパラメータを利用する
- `POST` / `PUT` は JSON のリクエストボディを利用する
- `DELETE` は基本的にパスパラメータで対象を指定する

### 6.2 レスポンス
- 取得系APIは対象データを返す
- 作成 / 更新 / 削除系APIは、対象IDと完了メッセージを返す
- 一覧取得APIで対象が0件の場合は空配列を返す

---

## 7. 検索・一覧表示方針

### 7.1 メモ一覧
- 検索対象は `title` および `content` とする
- 並び順は `created_at` 降順とする
- 新しいメモから順に表示する
- ページングは実装しない

### 7.2 カテゴリ一覧
- 全カテゴリを返す
- 0件の場合は空配列を返す

---

## 8. バリデーション共通方針

### 8.1 メモ
- `title` は必須、最大200文字、空文字不可
- `content` は任意、空文字可
- `category_id` は任意、指定時のみ形式・存在チェックを行う

### 8.2 カテゴリ
- `category_name` は必須、最大100文字、空文字不可、重複不可

### 8.3 認証
- 認証成功後のユーザー識別には `google_sub` を利用する
- アプリ内の識別には `user_id` を利用する

---

## 9. エラー時の基本方針

- 入力エラー時は `400 Bad Request` を返す
- 対象データが存在しない場合は `404 Not Found` を返す
- 一意制約違反は `409 Conflict` を返す
- 権限不足は `403 Forbidden` を返す
- サーバ内部エラーは `500 Internal Server Error` を返す
